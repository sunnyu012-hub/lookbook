# LITTLE LIFE v0.1

> 내 하루가 곧 캐릭터의 모험이 된다.

현실에서 작은 퀘스트를 완료하면 EXP를 얻고 캐릭터가 자라는 생활 RPG.
개인용 모바일 웹앱이고, v0.1은 백엔드·로그인 없이 localStorage만 쓴다.

## 실행

```bash
cd little-life
npm install
npm run dev      # http://localhost:5174
```

아이폰에서 볼 때는 같은 Wi-Fi에서 터미널에 찍히는 Network 주소로 접속하면 된다.
Safari에서 열고 "홈 화면에 추가"하면 앱처럼 전체화면으로 쓸 수 있다.

```bash
npm run build      # 타입 체크 + 프로덕션 빌드
npm run preview    # 빌드 결과 확인
npm run typecheck  # 타입만 확인
npm test           # 단위 테스트 (분류기 · 반복 · 레벨 · 보상 · 전투 · 도시 · 마이그레이션 · 백업 · 옮기기 · 안내 · 모습)
```

아이폰 홈 화면에 앱처럼 올리는 순서는 [DEPLOY.md](./DEPLOY.md) 에 있다.
오프라인에서도 열리고 퀘스트 완료까지 된다.

### 나중에 손댈 자리

- **밸런스** — `lib/level.ts`의 `BASE_EXP` / `STEP`, `lib/difficulty.ts`의 EXP 표,
  `lib/rpg/rewards.ts`의 `DIFFICULTY_COINS`
- **Supabase 연결** — `StateRepository`를 구현한 클래스를 하나 더 만들고
  `store/localStorage.ts` 마지막의 `repository` export만 교체한다.
  인터페이스가 이미 async라서 화면 코드는 건드릴 필요 없다.
- **캐릭터** — `CharacterAvatar`만 갈아끼우면 된다. 헤어/의상/액세서리/펫은
  `character/types.ts`의 `CharacterLook`에 필드를 늘리고,
  방 오브젝트는 `RoomBackground`, 배치는 `CharacterRoomCard`에서 다룬다.
- **데이터 확장** — `AppState`에 필드를 추가하고 `STATE_VERSION`을 올린 뒤
  `localStorage.ts`의 `sanitizeState`에서 기본값을 채운다.

## 설계 메모

- **통계는 퀘스트에서 유도하지 않고 따로 쌓는다.**
  `categoryStats`(누적)와 `dailyLog`(날짜별)를 별도로 두기 때문에,
  완료한 퀘스트를 지워도 이미 받은 EXP와 기록이 사라지지 않는다.
- **EXP는 생성 시점에 굳혀 저장한다.** 난이도 밸런스를 바꿔도 과거 기록이 흔들리지 않는다.
- **사용자를 혼내지 않는다.** 연속 기록, 경고, 캐릭터가 시무룩해지는 연출은 넣지 않았다.
  미완료 퀘스트는 날짜가 지나도 남아 있어서, 며칠 쉬었다 돌아와도 바로 이어서 할 수 있다.
  주간 목표도 못 채우면 그냥 다음 주가 온다 — 못 한 것을 세지 않는다.
- **`prefers-reduced-motion`** 을 켠 기기에서는 애니메이션이 거의 사라진다.
- **화면 글자는 전부 한국어다.** 짧은 라벨까지 영문으로 두면 읽는 속도가 한 번씩 끊긴다.
  이름·라벨은 `lib/labels.ts` 한곳에 모아뒀다.
  카테고리·난이도 배지 그림에는 영문이 그려져 있는데(그림은 못 고친다) 글자는 한국어로 읽히게 했다.
  `EXP` 만 단위로 남겼다 — km 처럼 읽히는 자리라 굳이 옮기지 않았다.

## 에셋

`public/assets` 아래 WebP 38장 (합계 약 800 KB). 첨부받은 스프라이트 시트에서
알파 채널 기준으로 조각을 잘라내 이름을 붙였다.

```
public/assets/
├── character/  idle · quest-clear · celebrate · resting + 얼굴 4종
├── room/       window · rug · beanbag · plant · shelf · desk · lamp · frame …
├── badges/     카테고리 6종 · 난이도 3종 · exp · level-up · quest-clear · check
└── effects/    sparkle · hearts · star · pop
```

경로는 `lib/assets.ts` 한 곳에만 적어둔다. 화면 컴포넌트는 파일명을 모르고,
나중에 옷·펫이 늘어나도 이 표만 고치면 된다.

배지 그림이 촘촘해서 20px 아래로 줄이면 뭉개진다.
그래서 섹션 제목 옆 같은 작은 자리에는 그림을 쓰지 않고,
28px 이상 확보되는 곳(카테고리 썸네일, 통계 칸, 난이도 선택)에만 쓴다.

### 캐릭터 포즈가 바뀌는 지점

| 상황 | 그림 |
|---|---|
| 오늘 할 퀘스트가 남아 있음 | 서 있기 (`idle`) |
| 오늘 할 퀘스트를 다 끝냄 | 빈백에 앉아 쉬기 (`resting`) |
| 퀘스트 완료 직후 약 1초 | 폴짝 (`questClear`) |
| 레벨업 | 만세 (`levelUp`) |

`resting` 은 "할 일이 없어서 쉬는 중" 이지 "못 해서 처진 상태" 가 아니다.
앉은 그림에는 빈백이 들어 있어서, 그때는 방에 놓인 빈백을 숨긴다.

빈 화면에는 얼굴을 띄운다. 아직 아무것도 없으면 차분한 얼굴,
오늘 몫을 다 했으면 웃는 얼굴, 필터 결과가 없으면 갸웃하는 얼굴.

### 아직 쓰지 않은 에셋

`lib/assets.ts` 의 `CHARACTER_EXTRA` 에 남겨뒀다.

- 팔 들고 윙크하는 포즈 — 업적 같은 게 생기면 쓸 자리
- 삐친 얼굴 — 캐릭터가 사용자를 탓하지 않기로 해서 화면에서는 쓰지 않는다
- 시트에 있던 깃발 / 자물쇠 / 달력·설정 버튼은 아직 해당 기능이 없어서 내보내지 않았다.
  BOSS 배지와 체력바는 CITY RPG 에서 필요해졌지만, 20px 아래로 뭉개지는 그림 대신
  글자 배지(`BossBadge`)와 `ProgressBar` 로 그렸다

## 벌이와 물건값

실제로 해보니 돈이 안 모여서 러그 하나 깔아볼 수가 없었다. 재보니 이랬다.

| | 옛날 | 지금 |
| --- | --- | --- |
| 퀘스트 하나 | 5 / 10 / 20 | **15 / 30 / 60** |
| 보통 하루 (3개) | 25 | **75** |
| 제일 싼 러그 (120) | 나흘 | 1.6일 |
| 중앙값 (160) | 엿새 | 2.1일 |
| EPIC 중앙값 (655) | 스무날 | 8.7일 |
| 페르시안 러그 (1800) | 두 달 | 24일 — 목표로 남겨둔다 |

**물건값은 안 건드렸다.** 값을 내리면 비싼 것까지 같이 싸져서 모을 이유가 사라진다.

이 규칙이 또 흐트러지지 않게 `rewards.test.ts` 에 "하루치로 뭘 살 수 있나" 를 박아뒀다.
하루치로 방에 놓을 것 열 개는 살 수 있고, 그렇다고 하루에 절반을 사버리지도 않는다.

옛 표로 받은 사람에게는 `한 퀘스트 = 20 코인` 으로 한 번 채워준다 (`grantCoinRebalance`).
`coinRebalanceGiven` 플래그로 막아서 두 번 열어도 두 번 주지 않는다.

## 이번 주 목표

도감 240개는 목표로 쓰기엔 너무 멀다. "언젠가 다 모은다" 는 오늘 뭘 할지 알려주지 않는다.
그래서 손에 잡히는 걸 매주 세 개만 내놓는다 (`lib/goals.ts`).

- 목표는 **저장하지 않는다.** 그 주 월요일 날짜가 씨앗이라 같은 주면 늘 같다
- 진행도도 **저장하지 않는다.** 이미 쌓고 있는 기록에서 센다 —
  `dailyLog` · `collection.discovered` · `collection.purchases`
- 저장하는 건 "이 목표의 보상을 받았다" 하나뿐이고, 여덟 주가 지나면 정리한다
- 채우면 **버튼 없이 그 자리에서** 코인이 들어온다 (`applyCollectionDerived`)
- 카테고리 목표는 개수가 아니라 **며칠**이다. 하루에 몰아서 하는 것보다 사흘에 나눠 하는 게 낫다

## 발견

"퀘스트 → 코인 → 구매" 만 돌면 며칠이면 다 본 앱이 된다.
그래서 **내가 이미 한 것에서 뒤늦게 나오는 것들**을 얹었다.

### 진행도를 저장하지 않는다

이 층에서 저장하는 건 "무엇을 이미 봤는지 · 받았는지" 뿐이다.
숫자는 전부 원래 쌓이고 있던 것에서 다시 센다 —
`categoryCompleted` · `usageProfiles` · `reputation` · `dailyLog` · `npcs`.

그래서 **backfill 코드가 없다.** 업데이트를 켜는 순간 예전 기록이 그대로 반영된다.
BODY 퀘스트를 이미 서른 개 한 사람은 0 부터 시작하지 않는다.
조건을 나중에 바꿔도 저장된 값과 어긋날 일이 없다.

### 앱이 나중에 알아보는 것 (`lib/discovery/collections.ts`)

여덟 가지. 목표를 세우게 하는 기능이 **아니다** — 할 일을 하나도 더 얹지 않는다.

| | 무엇을 보는가 | 완성 |
|---|---|---|
| 👟 움직인 날들 | BODY 퀘스트 | 12 |
| 🌙 밤에 깨어 있는 사람 | 밤에 끝낸 퀘스트 | 10 |
| 🧹 집을 돌본 흔적 | LIFE 퀘스트 | 20 |
| 🖋️ 집중하던 시기 | WORK 퀘스트 | 15 |
| ☁️ 쉬어간 날들 | MIND 퀘스트 | 12 |
| 🗺️ 여기저기 다녀본 사람 | 활동한 동네 수 | 4 |
| 💗 사람들과 지낸 시간 | 친밀도 합 | 40 |
| 🎟️ 주말에도 나선 사람 | 뭔가 한 주말 | 8 |

**줄어들지 않는다.** 세는 값이 전부 "지금까지 몇 번" 이라 애초에 내려갈 수가 없다.
며칠 쉬어도 7/10 이 0 이 되지 않는다.

**트로피를 주지 않는다.** 트로피에는 이미 "그 분야 100개" 조건이 붙어 있어서,
12개에 줘버리면 100개짜리가 영영 의미를 잃는다. 결이 맞는 평범한 물건을 준다.

### 도시 안쪽 (`lib/discovery/secrets.ts`)

다섯 곳. **모름 → 낌새 → 발견** 세 단계다.

달빛 골목 · 뒷방 · 옥상 정원 · 오래된 오락실 · 조용한 구석.

- 모르는 곳은 지도에 아무것도 안 뜬다. 전부 그려두면 그건 지도가 아니라 목록이다
- 조건을 **숫자로 보여주지 않는다.** "밤거리 5/7" 은 진행바지 발견이 아니다.
  대신 "이 근처가 조금 익숙해졌다" 라고 쓴다
- 조건이 여럿이면 **제일 덜 온 것**으로 본다. 평균으로 하면 한쪽만 채워도 낌새가 떠서,
  갔다가 허탕을 친다
- 한 번 찾으면 다시 잠기지 않는다

### 도시 사람 이야기 (`lib/discovery/stories.ts`)

미나 4장 · 하루 3장 · 루루 3장 · 노아 3장.

한 장은 **서너 줄**이다. 폰에서 스크롤 없이 읽히는 길이 —
길게 쓰면 안 읽고 넘기게 되고, 그러면 안 쓴 것과 같다.

**퀘스트를 시키지 않는다.** 조건은 이미 하고 있는 것(그 동네에 얼마나 있었나,
얼마나 자주 만났나)으로만 잡는다. 읽는 것 자체가 보상이다.
앞 장을 읽어야 다음 장이 열린다.

미나 4장은 뒷방을, 노아 3장은 달빛 골목을 연다.

### 같이 다니는 것들 (`lib/discovery/companions.ts`)

보리(강아지) · 모찌(고양이) · 콩(작은 새) · 루나(모르겠다).

**키우는 게 아니다.** 밥을 안 줬다고 배고파하지 않는다. 병들지 않는다.
도망가지 않는다. 죽지 않는다. 그런 걸 넣는 순간 동료가 아니라 매일 확인해야 하는 알림이 된다.

- 사는 게 아니라 **만난다** — 동네에 오래 있거나, 비밀 장소를 찾거나
- 친밀도는 **내려가지 않는다.** 안 만나면 그냥 안 오르는 것뿐이다
- 인사는 하루 한 번만 오른다. 여러 번 눌러도 되지만 그때는 안 오른다 —
  눌러야 이득인 버튼을 만들면 그때부터 그건 숙제다
- 친해지면 **기억**이 하나씩 열린다. "비 오던 오후 — 처마 밑에서 같이 비가 그치기를 기다렸다."

**자세가 여덟 개씩 있다.** `public/assets/companions/<이름>/<자세>.webp`.
화면에서 쓰는 건 둘이다 — 목록에서는 `idle`, 같이 다닐 때는 `walk`.

자세 이름은 **줄마다 실제 그림을 보고** 붙였다. 순서가 마리마다 달라서 —
고양이 다섯 번째는 자는 게 아니라 기지개(`stretch`)고 자는 건 여섯 번째다.
여기서 대충 붙였으면 나중에 `sleep` 을 불렀는데 기지개가 나온다.

그림이 안 뜨면 이모지로 돌아간다. 캐시가 비었거나 오프라인 첫 실행이면
잠깐 그럴 수 있는데, 그때 빈칸이 남으면 자리가 무너져 보인다.

```bash
npm run assets:companions   # 시트 → public/assets/companions/
```

**옆 그림이 딸려오는 것**만 걸러낸다. 자세끼리 붙어 있는 줄이 있어서
상자만 잘라내면 강아지가 뛰는 그림에 자는 그림 조각이 붙는다.
덩어리 번호로 한 번 더 거르는데, **작다고 다 지우지는 않는다** —
루나 주위의 별이 작은 덩어리라 그러면 별이 사라진다.
빼는 건 "옆 자세의 몸통" 뿐이다.

### 도감 힌트 (`lib/discovery/hints.ts`)

`???` 에 찾아갈 이유를 준다. 네 단계.

| | |
|---|---|
| 0 | 언제 만나게 될지는 아직. |
| 1 | 어느 가게 진열대에서 본 적이 있는 것 같다. |
| 2 | 창작 골목의 어느 가게에 들어온다. |
| 3 | 준의 빈티지에 가끔 들어와. |

가게에서 본 적이 있으면 1, 그 동네에서 얼굴이 알려지면 2,
도감을 마흔 개쯤 채우면 3. **오래 막아두지는 않는다** —
못 찾아서 답답한 것과 못 찾게 막는 것은 다르다.

비밀 물건은 끝까지 1단계를 안 넘는다. 알려주는 순간 비밀이 아니다.

### 한꺼번에 쏟지 않는다

업데이트 직후에는 예전 기록 덕에 여러 개가 동시에 열린다.
팝업을 열 개 연속으로 띄우면 그건 축하가 아니라 사고다.

화면에는 **하루 세 개까지만** 올리고, 나머지는 발견함에 쌓인다.
못 본 채로 지나가는 건 없다.

## 오늘의 가게

"오늘 물건이 새로 깔렸어" 는 매일 참이라 며칠이면 안 읽힌다.
그래서 **오늘만 참인 것**을 만들었다.

- **오늘 싸게** — 가게마다 하루 한둘, 25% 깎아준다. 귀한 건 안 깎는다 (EPIC 하나가 25% 빠지면 그날이 다른 날 열흘이 된다)
- **오늘까지** — 내일 진열에 없는 것. 진열은 날짜만 알면 나오는 값이라 하루 앞뒤로 한 번 더 굴리면 된다
- 둘 다 저장하지 않는다. 홈의 도시 카드에는 이 둘을 먼저 올린다

### 귀한 것은 드물어야 귀하다

처음에는 가게 목록에서 그냥 아무거나 N개를 뽑았다. 60일치를 세어보니 결과는 이랬다:

| | 예전 | 지금 |
|---|---|---|
| 준의 빈티지에서 전설품이 차지하는 칸 | **21%** | 7% |
| 취미 코너에서 EPIC 이 차지하는 칸 | **27%** | 12% |

다섯 칸 중 한 칸이 매일 전설품이면 그건 전설품이 아니라 그냥 재고다.
그래서 `lib/collection/rotation.ts` 에서 **등급마다 뽑힐 무게**를 다르게 준다 —
COMMON 60 · RARE 28 · EPIC 10 · LEGENDARY 2, SECRET 은 0 (가게에 절대 안 나온다).

**무게는 등급 전체의 몫이지 한 물건의 몫이 아니다.** 그 등급에 몇 개가 있는지로 나눠준다.
안 나누면 전설품이 세 개인 가게에서는 전설품 몫이 저절로 세 배가 된다 — 처음 버그가 이거였다.

가게마다 그 위에 배율을 얹는다. 작은 생활 마켓은 COMMON ×1.4,
준의 빈티지는 LEGENDARY ×3, 달빛 가판은 EPIC ×2.5.
여덟 곳이 같은 확률표를 쓰면 아이콘만 다른 같은 가게가 여덟 개다.

무게만 두면 준의 빈티지에 흔한 것만 깔리는 날이 생기니까,
**보장 칸**을 둔다 (홈 아틀리에 1칸, 준의 빈티지 2칸). 대신 제일 흔한 칸을 내주고 바꾼다 —
칸 수가 늘어나면 안 된다.

### 재고와 품절

물건마다 하루 재고가 있다. 흔한 것 3개, EPIC·LEGENDARY·빈티지는 1개, 먹을 것과 재료는 5개.

**재고도 저장하지 않는다.** `하루 재고 − 오늘 산 개수` 로 계산한다.
오늘 산 개수는 원래부터 `collection.purchases` 에 있었다.
그래서 진열을 몇 번을 다시 계산해도 구매 기록을 덮어쓸 일이 없다.

다 나가면 `SOLD` 로 자리를 남긴다. 지우지 않는다 — 아침에 있던 게 어디 갔는지 알 수가 없어진다.

### 오늘의 입고

가게에 들어가기 전에 볼 것이 있는지 알 수 있어야 한다. 없으면 안 열어도 된다.

- 가게 위에 `새로 들어온 것 N개 · 찾던 물건 N개 · 처음 보는 것 N개`
- 새 날 첫 방문이면 `RESTOCKED ✦` 한 번. 전체 화면 팝업은 만들지 않았다
- 그날 제일 귀한 한 칸에 `오늘의 발견`. **살 수 있는 것 중에서만 고른다** —
  못 사는 물건을 가리키는 건 알려주는 게 아니라 약 올리는 것이다
- 아래에 `이 가게 물건 13개 중 4개를 도감에 넣었어`. 남은 목록은 펼치지 않는다

**딱지는 등급 말고 하나만 붙인다.** NEW · 오늘 싸게 · 오늘까지 · 처음 보는 것을 다 붙였더니
한 줄에 네 개가 되어 정작 물건 이름이 안 읽혔다.

### 본 것과 가진 것은 다르다

가게 진열대에서 본 물건은 `seen` 으로 적어둔다. 도감에서 이름과 그림이 옅게 보이고
`본 적 있음` 이 붙지만, **발견 수에는 안 들어간다.** 봤다고 모은 게 되면 모으는 재미가 없다.

`UNKNOWN` → `SEEN` → `DISCOVERED`. 비밀 물건은 봐도 계속 `???` 다.

### 자주 오면

지역 평판이 오르면 그 동네 가게가 조금씩 달라진다. **단계마다 하나씩만** 붙는다.

| 단계 | 붙는 것 |
|---|---|
| 2 · 자주 오는 사람 | RARE 이상 무게 ×1.4 |
| 3 · 여기 사람 | 진열 한 칸 더 |
| 4 · 반가운 얼굴 | 보장 칸 하나 더 |
| 5 · 이 동네의 전설 | 전설품 무게 ×2 |

한꺼번에 세게 붙이면 평판 낮은 동네의 가게가 볼 것 없는 가게가 된다.
다섯 단계를 다 올려도 진열은 두 칸까지만 는다.

### 레벨로 열리는 것

EPIC 은 4레벨부터, LEGENDARY 는 8레벨부터 진열대에 오른다.
시작하자마자 전설품이 있으면 살 수가 없으니 그냥 벽지가 되고, 나중에 열리면 레벨이 오른 게 눈에 보인다.
흔한 것에는 조건이 없다 — **첫날에도 살 것이 충분해야 한다.**

### 문 앞에 온 상자

이 앱에서 유일하게 아무것도 안 하고 받는 것이다. **열하루에 한 번쯤** 온다.

- 올지 안 올지는 날짜에서 계산한다. 저장하는 건 "받았다" 뿐이다
- 확률만 두면 이틀 연속으로 오는 날이 생겨서, 앞의 사흘을 보고 이미 왔으면 오늘은 안 온다
- RARE·EPIC 중에서 아직 도감에 없는 것을 먼저 보낸다. 전설품은 안 보낸다 — 그건 찾아가서 만나야 한다
- **열기 전에는 뭔지 안 알려준다.** 미리 보여주면 받을지 말지를 고르게 되고, 그러면 선물이 아니라 선택이 된다
- 안 받고 넘겨도 아무 말 안 한다. 다음 날이면 그냥 없어진다

### 기존 데이터

`STATE_VERSION = 8`. `collection` 에 칸 세 개가 는다 — `seen` · `shopVisits` · `claimedDeliveries`.

**없는 칸만 채운다.** 코인 · 도감 · 가진 것 · 방에 놓아둔 것 · 찾는 물건은 손대지 않는다.
구매 기록은 남은 재고를 세는 데만 쓰니까 최근 이레치만 남기고 정리한다 —
안 그러면 몇 달 뒤 저장소에 아무도 안 보는 줄이 수천 개 쌓인다.

## 퀘스트 입력 줄이기

타이핑이 귀찮아서 앱을 안 열게 되는 게 가장 큰 이탈 요인이라, `lib/suggest.ts` 에 세 가지를 뒀다.
AI 는 쓰지 않는다 — 규칙과 내 기록만 본다. 즉시 뜨고, 오프라인에서도 되고, 쓸수록 내 말투에 맞아간다.

**추천** — 시트 맨 위 한 줄. 누르면 제목·카테고리·난이도가 한꺼번에 채워진다.
전에 완료한 적 있는 것을 많이 한 순서로 먼저 보여주고, 기록이 없으면 시간대별 기본 추천을 쓴다.
아직 안 끝낸 퀘스트는 추천하지 않는다 — 눌러봤자 같은 게 두 개가 될 뿐이다.

### 한 칸은 늘 처음 보는 것

"퀘스트가 다 비슷비슷하다" 는 말을 듣고 세어봤더니 기분이 아니라 산수였다.

| | 예전 | 지금 |
|---|---|---|
| 준비된 퀘스트 중 추천에 뜰 수 있는 것 | 47 / 112 | **142 / 142** |
| 밤에 후보가 되는 것 | 7개 | 142개 |
| 기록이 쌓인 뒤 추천 여섯 칸 중 처음 보는 것 | **0칸** | 2칸 |

두 가지가 겹쳐 있었다.

**하나.** 시간대가 안 적힌 세트 열한 개가 후보에서 통째로 빠져 있었다.
`bands` 가 없으면 "언제든" 이라는 뜻인데 코드는 "절대 안 됨" 으로 읽고 있었다.
그래서 준비된 퀘스트 112개 중 65개가 **한 번도** 추천에 안 나왔다.
이제 시간대는 거르는 조건이 아니라 순서를 정하는 값이다 — 아침 세트가 아침에 앞에 올 뿐,
나머지가 사라지지는 않는다.

**둘.** 추천은 내 기록만 점수순으로 세웠다. 그래서 기록이 예닐곱 개만 쌓이면
여섯 칸이 전부 예전에 한 것으로 찼고, 그때부터 앱은 **구조적으로** 새로운 걸 못 보여줬다.
이제 두 칸은 떼어둔다 (`lib/library/fresh.ts`).

- 한 번도 안 해본 것이 제일 무겁고, 한 달 넘게 안 한 것이 그다음이다
- **요즘 손 안 댄 분야**가 더 자주 걸린다. 개수가 아니라 며칠 손댔는지로 센다 —
  하루에 청소를 다섯 개 한 것과 닷새에 걸쳐 하나씩 한 것은 다른 이야기다
- 두 칸이 같은 분야로 차지 않는다
- 날짜가 씨앗이라 그날 하루는 같은 것이 나온다. 고르는 중에 바뀌면 누를 수가 없다
- 덜 보겠다고 한 것은 새것으로도 안 내민다

**안 했다고 말하지 않는다.** "요즘 운동 안 했네" 는 이 앱이 절대 하지 않기로 한 말이다.
그냥 `🌱 새로 해볼까` 를 달아 내밀 뿐이고, 안 누르면 내일 다른 게 온다.

기록이 아직 적으면 자리를 떼지 않는다 — 어차피 아래에서 준비된 퀘스트로 채워진다.
새것이 절반을 넘지도 않는다. 그러면 그건 추천이 아니라 남의 목록이다.

### 하고 싶은 것도 목록에 있어야 한다

"딱히 하고 싶은 것도 없어" 에 답하려면 앱이 내밀 게 있어야 하는데,
준비된 퀘스트 112개 중 놀이가 5개 · 관계가 6개뿐이었다. 나머지는 전부 챙겨야 할 일이었다.

세트 다섯 개를 더 썼다 — **밖에 나가기 · 혼자 노는 시간 · 손으로 만들기 ·
나를 위한 작은 것 · 사람 만나기**. 142개가 됐고 놀이 19 · 관계 13 · 마음 20 이 됐다.

생활·일만 하는 사람으로 한 달을 돌려보면 새것 43가지가 뜨고,
그중 몸 19 · 마음 15 · 놀이 13 · 관계 7 로 **하던 것 반대쪽**이 나온다.

**자동 분류** — 제목을 치는 동안 카테고리를 고른다.
예전에 같은 제목으로 만든 적이 있으면 그때 고른 값을 그대로 쓴다 (사전보다 내 기록이 늘 정확하다).
없으면 한국어 키워드 사전을 쓰고, 긴 단어에 가중치를 준다 —
"생각 정리" 가 "정리" 를 이겨야 LIFE 가 아니라 MIND 로 간다.
짚이는 게 없으면 비워둔다. 아무거나 찍지 않는다.

**자동 난이도** — "30분", "1시간 30분" 같은 표현을 분으로 읽어 25분 미만은 Easy,
60분 이상은 Hard 로 잡는다. 시간 표현이 없으면 "가볍게 / 잠깐" · "대청소 / 밀린" 같은 힌트를 본다.

**직접 고르면 자동은 멈춘다.** 골라놓은 걸 타이핑할 때마다 되돌려버리면 그것만큼 짜증나는 게 없다.
값 옆의 `자동` · `기억해둔 것` 표시는 앱이 대신 골랐다는 뜻이고, 누르면 바로 바뀐다.

규칙이 많아 눈으로는 놓치기 쉬워서 `src/lib/__tests__/suggest.test.ts` 에 48개,
추천이 한 쪽으로 굳지 않는지는 `fresh.test.ts` 에 24개를 두고 돌린다.

## 반복 퀘스트

매일 같은 걸 다시 입력하는 게 가장 큰 마찰이라, 아예 안 치게 만들었다.
퀘스트를 만들 때 **매일 / 평일 / 요일 선택** 중 하나를 켜두면 해당하는 날 아침에 알아서 생긴다.

`Routine` 은 조리법이고 `Quest` 는 거기서 나온 오늘 몫이다. 둘을 한 타입에 섞으면
"이게 원본인가 오늘 것인가" 가 늘 헷갈려서 나눴다. 오늘 몫에는 `routineId` 가 붙는다.

**밀린 걸 몰아서 만들지 않는다.** 3일 만에 열었다고 퀘스트 3개가 쌓여 있으면
그것만으로 앱을 닫게 된다. 언제 열든 오늘 것 하나만 만든다.

같은 제목이 이미 오늘 목록에 있거나 오늘 이미 완료했으면 또 만들지 않는다.
직접 만들어 둔 것과 겹치지 않게 하려는 것이다.

앱을 열 때와, 켜둔 채 날짜가 바뀌었다가 다시 볼 때 (`visibilitychange`) 검사한다.
홈 화면에 추가해두면 며칠씩 안 닫는 경우가 많아서 후자가 필요하다.

QUEST 화면 아래 **Repeat** 목록에서 잠시 멈추거나 그만둘 수 있다.
그만둬도 오늘 이미 만들어진 퀘스트는 남는다 — 이미 내 오늘 몫이다.

## 고치기 · 미루기 · 되돌리기

퀘스트 메뉴(⋯)에서:

- **고치기** — 제목·카테고리·난이도를 바꾼다. 아직 안 끝낸 것만 고칠 수 있다.
  이미 완료한 걸 고치면 지난 통계와 어긋나서, 그건 되돌린 뒤에 고치게 했다.
  난이도를 바꾸면 아직 안 받은 EXP 라 값도 같이 따라간다.
- **내일로 미루기** — 오늘 목록에서만 감춘다 (`snoozedUntil`). 지우는 게 아니라 미루는 것이다.
- **완료 되돌리기** — 완료 직후 토스트에서도, 나중에 완료 목록 메뉴에서도 된다.

되돌리기는 `totalExp` 에서 빼고 `levelFromTotalExp` 로 레벨을 다시 계산한다.
되돌리다 레벨이 내려가는 경우까지 정확히 맞는다 — 그 함수가 `applyExp` 를 처음부터
쌓은 결과와 늘 같기 때문이고, 그걸 테스트로 묶어뒀다 (`level.test.ts`).
카테고리 통계와 그날 기록에서도 함께 빠진다. 어제 완료한 걸 오늘 되돌려도 어제 칸에서 빠진다.

## CITY RPG

현실을 게임으로 한 겹 더 읽는 층. 검·갑옷·성 대신 머그컵·헤드폰·운동화·카페·공원으로 만든다.

| 현실 | 게임 |
| --- | --- |
| 오늘 할 일 | Daily Quest |
| 미뤄둔 일 | Monster |
| 크고 오래 걸리는 일 | Boss |
| 있는 장소 | Area |
| 늘 쓰는 물건 | Equipment |

- **MAP** — 지역 6곳. 지금 있는 곳의 버프가 보상에 붙는다. Night Town 은 21시부터 열리고,
  밤이 지나면 조용히 Home Base 로 돌아온다. 닫힌 곳의 버프를 계속 받게 두면 지도의 규칙이 거짓말이 된다.
- **BAG** — 인벤토리와 6칸 장비(HEAD / TOP / BOTTOM / SHOES / ACCESSORY / CHARM).
- **QUEST** — DAILY / MONSTER / BOSS 세 갈래. 몬스터·보스는 큰 일을 작은 행동으로 쪼갠 목록이고,
  하나 누를 때마다 HP 가 깎인다. **시간 제한이 없고 HP 가 도로 차지 않는다.**
  며칠 쉬어도 진행도가 사라지지 않고, 잘못 눌렀으면 UNDO 로 되돌린다.
- **ME** — 직업 5종과 스탯 6종, 장비 슬롯. 직업은 언제든 바꿀 수 있고 바꿔도 잃는 게 없다.

### 보상 한 줄기

퀘스트 완료 → EXP · Coin · Stat · Drop 이 전부 `lib/rpg/rewards.ts` 한 곳을 지난다.
직업·장비·지역이 모두 같은 모양(`Bonuses`)으로 보너스를 내놓기 때문에, 계산하는 쪽은 출처를 모른다.

**퍼센트는 곱하지 않고 모두 더한 뒤 한 번에 적용한다.** 곱하면 장비를 몇 개 꼈는지에 따라
값이 튀어서 예측이 안 된다 (`rewards.test.ts` 가 HARD 난이도에서 이 둘이 다르다는 걸 잡아둔다).

받은 값은 `quest.reward` 에 그대로 적어둔다. 되돌리기가 정확히 반대로 돌려면
그때 무엇을 받았는지 알아야 하고, 떨어졌던 아이템도 같이 회수한다 —
안 그러면 완료·되돌리기를 반복해서 계속 주울 수 있다.

`EXPLORER` 의 패시브는 명세의 "Random Quest reward +10%" 를 지금 구조에 맞춰
**모든 퀘스트 Coin +10%** 로 옮겼다. 무작위로 어떤 퀘스트에만 붙으면 왜 값이 달라졌는지
화면에서 설명할 방법이 없다.

### 기존 데이터

`STATE_VERSION = 3`. 올릴 때 **기존 기록은 하나도 지우지 않는다.**
없는 항목만 기본값으로 채우고 있는 값은 손대지 않는다 (`store/migrate.ts`).
없어진 아이템이 슬롯에 남아 있거나 정의가 사라진 몬스터가 저장돼 있으면 조용히 비운다.

업데이트하고 처음 열면 Welcome Gift(Favorite Mug + 50 Coin)를 한 번 준다.
`welcomeGiftGiven` 플래그로 막아서 다시 열어도 또 주지 않는다.

## CITY LIFE

RPG 시스템이 있는 생활 앱에서, 사람과 사건이 있는 도시로 한 겹 더 넓혔다.
NPC · 상점 · 이벤트는 앱 안에 오래 붙잡아두려고 두는 게 아니라,
**현실에서 뭔가 해보고 싶게 만드는 장치**로만 쓴다. 모든 성장의 원천은 여전히 현실 행동이다.

### 도시 사람 6명

| 이름 | 자리 | 하는 일 |
| --- | --- | --- |
| Mina | Cafe Street | 카페 주인 · WORK · MIND 의뢰 · 커피와 차를 판다 |
| Haru | Green Park | 아침에 뛰는 사람 · BODY · HEART 의뢰 |
| Lulu | Creative District | 만드는 사람 · PLAY · MIND 의뢰 |
| June | Creative District | 빈티지 가게 주인 · 옷과 장신구를 판다 |
| Rio | Training Zone | 코치 · BODY 의뢰 · 운동 장비를 판다 |
| Noa | Night Town | 밤에만 보이는 사람 · 밤 시장 |

**친밀도는 시간이 지나도 줄지 않는다.** 며칠 안 와도 아무도 서운해하지 않는다.
하루 첫 인사(+2), 선물(+5, 좋아하는 결이면 +10), 의뢰 완료(+10)로만 오른다.
계속 눌러서 올릴 수 있으면 대화가 버튼이 되기 때문에, 대화는 하루 한 번만 센다.

### NPC 의뢰

`questType: 'NPC'` 인 보통 Quest 다. 기존 완료 파이프라인을 그대로 지나서
EXP · Coin · Stat · Drop 을 받고, 그 위에 친밀도와 평판이 얹힌다.

**다음 단계는 앞 단계를 끝낸 뒤에 하나씩 열린다.** 3단계를 한꺼번에 던져주면
그 자체로 밀린 일이 된다. 되돌리면 그때 열렸던 다음 단계도 같이 거둔다 —
안 그러면 되돌릴 때마다 퀘스트가 하나씩 늘어난다.

### 상점 · 이벤트 · 오늘의 도시

**오늘 뭐가 열렸는지는 저장하지 않는다.** 날짜를 씨앗 삼아 그 자리에서 계산한다
(`lib/city/seed.ts`). 새로고침해도 같은 결과가 나오고, 자정이 지나면 알아서 바뀌고,
저장할 게 없으니 어긋날 것도 없다.

이벤트는 하루 1~3개. **전부 보너스뿐이고 벌점은 하나도 없다** — "오늘 안 왔으니 손해" 를
만들지 않으려는 것이고, 테스트로 묶어뒀다.

### 스킬

6갈래 × 3단계 = 18개. 앞 단계를 찍어야 뒤가 열린다.

**스킬 포인트는 따로 쌓지 않고 레벨에서 계산한다** (`레벨 - 1 - 쓴 만큼`).
따로 쌓아두면 완료를 되돌려 레벨이 내려가도 포인트가 남고, 완료·되돌리기를 반복해서
포인트만 불릴 수 있다. 상태가 바뀔 때마다 `withSkillPoints` 가 다시 계산해 덮는다.

### 보상 파이프라인

출처가 여섯 개로 늘었지만 계산하는 곳은 여전히 `lib/rpg/rewards.ts` 하나다.

```
직업 → 장비 → 지역 → 스킬 → 평판 → 도시 이벤트 → 마신 것
                    ↓
        전부 같은 모양(Bonuses)으로 합쳐진 뒤 한 번에 적용
```

퍼센트는 여전히 곱하지 않고 더한다. 출처가 늘어날수록 곱셈은 더 빨리 튄다.

### 기존 데이터

그때 `STATE_VERSION` 을 4 로 올렸다. 없는 항목만 채우고 있는 값은 손대지 않는다.
없어진 스킬·아이템이 저장돼 있으면 조용히 버리고, 정의가 사라진 NPC 도 마찬가지다.
v3 데이터를 심어서 이름·레벨·Coin·직업·장비·통계·인벤토리가 그대로 남는지 브라우저로 확인한다.

## 퀘스트 라이브러리

"오늘 뭐 하지" 를 매번 타이핑으로 답하게 만들면 결국 앱을 안 열게 된다.
`＋` 를 누르면 곧장 빈 입력칸이 뜨는 대신 **새 퀘스트 허브**가 열린다 —
찾기 / 지금 추천 / 빠른 추가 / 추천 세트 / 직접 만들기 다섯 갈래다.
직접 만들기는 없애지 않았다. 맨 아래에 그대로 있다.

여기서도 **외부 AI 는 쓰지 않는다.** 점수 계산은 전부 이 기기 안에서 끝나고,
퀘스트 제목이 밖으로 나가는 경로 자체가 없다. 그래서 오프라인에서도 즉시 뜬다.

### 세트 18개

`lib/library/packs.ts` 에 아침·잠들기 전·회복·가볍게 움직이기·집 리셋·업무 시작·
집중·퇴근 후·취미·관계·주말 리셋·돈·디지털·기운 없는 날 … 18묶음.
세트를 열면 체크박스로 여러 개를 한 번에 고르고, **오늘만 / 루틴으로** 를 한 번만 정한다.
다섯 개를 고른 뒤 각각 반복 설정을 하라고 하면 그게 다시 일이 된다.

오늘 이미 있는 것은 체크 자체가 막히고 "오늘 이미 추가된 퀘스트야" 로 표시된다.

### 쓸수록 배우는 것

완료를 누를 때마다 `usageProfiles` 에 한 줄이 쌓인다 — 몇 번 넣었고 몇 번 끝냈는지,
**무슨 요일**에 했는지, **어느 시간대**에 했는지. 과거 기록을 매번 다시 훑지 않고
그 순간에만 더한다. 그래서 퀘스트가 몇 백 개가 돼도 허브는 즉시 열린다.

추천 점수는 이렇게 더한다:

```
자주 함 + 완료율 + 최근에 함 + 이 요일에 함 + 이 시간대에 함
        + 즐겨찾기 + 오늘 루틴 차례 − 덜 보기 누른 만큼
```

한 카테고리가 6칸을 다 먹지 않게 최대 4개까지만 넣고, 나머지는 다른 갈래로 채운다.
기록이 5개 미만이면 시간대에 맞는 기본 추천으로 채운다 — 첫날에도 빈 화면은 안 뜬다.

**추천 순서는 저장하지 않는다.** 열 때마다 다시 계산한다.
저장해두면 자정이 지나도 어제 순서가 남고, 요일·시간대가 바뀐 걸 놓친다.

**추천은 어디까지나 추천이다.** 앱이 알아서 퀘스트를 만들어 넣는 경로는 없다.
누르는 건 늘 사용자다. 마음에 안 들면 `⋯` 에서 오늘만 숨기거나 덜 보게 할 수 있고,
나 화면 **퀘스트 추천** 에서 통째로 끌 수도 있다.
`추천 기록 초기화` 는 추천 순서만 처음으로 돌린다 — 퀘스트·EXP·루틴·완료 기록은 그대로다.

### 되돌리기

완료를 되돌리면 EXP·Coin 뿐 아니라 학습 기록도 정확히 되돌아간다.
완료 횟수, 그 요일·시간대 칸, 최근 완료 날짜까지 함께 뺀다.
안 그러면 완료·되돌리기를 반복해서 추천 순위를 밀어올릴 수 있다.

### 루틴

세트에서 고른 걸 한 번에 루틴으로 만들 수 있고, **주 3회** 같은 빈도가 생겼다.
요일을 정하는 대신 이번 주에 몇 번 했는지를 세서 모자라면 오늘 하나 만든다.
시간대(아침·낮·저녁·자기 전)는 **표시일 뿐 알림이 아니다.** 정한 시각에 울리지 않는다.

### 기존 데이터

`STATE_VERSION = 5`. `usageProfiles` 와 `recommendSettings` 만 새로 채운다.
비어 있으면 **이미 쌓인 퀘스트 기록에서 되채운다** — 오래 쓴 사람일수록
업데이트 직후부터 바로 자기 추천이 뜬다.

기록의 열쇠는 세트에서 온 것이면 `팩:항목` 이고, 직접 쓴 것이면 공백을 지운 제목이다.
불러올 때 이 규칙을 다시 적용해서, `물 마시기` 와 `물마시기` 처럼 같은 것이
두 줄로 갈라져 있으면 하나로 합친다 (횟수는 더하고, 시각은 나중 것을 남긴다).


## 수집과 방

Quest → Coin → 가게 → 발견 → 도감 → 방. 이 고리가 이 업데이트의 전부다.
목표는 "좋은 장비를 맞추는 것" 이 아니라 **"오늘은 또 뭘 발견할까"** 하나다.

### 물건 240개

`lib/collection/items.ts` 한 장이 이 시스템의 전부다. 화면 코드에는 아이템 이름이 하나도 없다.
표에 한 줄을 더하면 상점·도감·제작·드롭·위시리스트가 전부 알아서 안다.

한 줄은 이렇게 읽는다:

```
[id, 이름, 이모지, 등급, 가격, 한 줄 설명, 획득처]
```

등급은 흔함 49% · 귀함 30% · 특별 15% · 전설 5% · 비밀 2% 쯤으로 흩어져 있다.
**목록 뒤로 갈수록 좋아지는 식이 아니다** — 물건의 분위기와 얻는 방법을 보고 하나씩 정했다.

설명은 한 줄씩 다 다르게 썼다. "분홍색 의자입니다" 같은 건 한 줄도 없다.

> 졸린 곰 쿠션 — 아무것도 안 했는데 같이 피곤해 보인다.
> 작은 달 조명 — 불을 끄기 전 마지막 빛.
> 비밀 서랍장 — 안에 뭐가 있었는지는 나만 안다.

### 절반 넘게는 가게 밖에 있다

240개가 전부 상점 물건이면 지도를 열 이유가 없어진다. 그래서 이렇게 흩어놨다:

| 어디서 | 몇 개 |
| --- | --- |
| 가게에서 판다 | 107 |
| 만들어야 생긴다 | 36 |
| 퀘스트를 하다 나온다 | 24 |
| 도시 사람이 준다 | 19 |
| 세트를 완성하면 | 13 |
| 보스를 넘으면 | 12 |
| 그날 도시에 무슨 일이 있으면 | 12 |
| 동네에서 얼굴이 알려지면 | 10 |
| 조건을 안 알려주는 것 | 6 |
| 현실에서 쌓이면 (트로피) | 1 |

도감에서 아직 못 만난 칸에는 **갈 곳을 알려준다.** "어디선가" 로 끝나면 그건 힌트가 아니다.
비밀 물건만 그마저도 안 알려준다 — 알려주는 순간 그건 숙제가 된다.

### 가게 8곳

홈 아틀리에 · 작은 생활 마켓 · 초록 온실 · 페이퍼 문 · 취미 코너 ·
준의 빈티지 · 주말 벼룩시장 · 달빛 가판.

무엇을 파는지는 아이템 표가 정한다 (`S:가게id`). 가게 파일에 목록을 또 적으면 두 곳이 어긋난다.

**하루에 그중 일부만 깔린다.** 날짜와 가게 이름이 씨앗이라 새로고침해도 그대로고,
자정이 지나면 바뀐다. 저장하지 않으니 기기마다 다른 진열이 남을 일도 없다.

- 벼룩시장은 토·일에만 서고, 값이 그 주 동안 ±20% 안에서 흔들린다
- 달빛 가판은 밤 9시부터 새벽 5시까지
- 준의 빈티지는 몇 번 와본 사람에게만 **전설품**을 꺼낸다 (지역 평판 10)
- 오늘 처음 들어온 것에는 `NEW`, 아직 못 만난 것에는 `처음 보는 것`,
  찾던 물건에는 `♥` 가 붙는다
- 지도에서 오늘 아직 안 들른 가게에는 `NEW STOCK` 이 붙는다.
  안 갔다고 뭐라 하는 게 아니라 어디를 보면 되는지만 알려준다

**하루에 몇 칸을 까는지는 파는 것의 수에 맞춘다.** 아홉 개 중 일곱 개를 매일 깔면
그건 진열이 아니라 목록이다. 지금 수치 (평판 1단계 · Lv.20 · 60일):

| 가게 | 파는 것 | 하루 진열 | 어제 없던 것 |
|---|---|---|---|
| 홈 아틀리에 | 34 | 11.8 | 6.8 |
| 작은 생활 마켓 | 18 | 10.0 | 4.5 |
| 초록 온실 | 11 | 6.0 | 2.8 |
| 페이퍼 문 | 12 | 6.1 | 3.0 |
| 취미 코너 | 15 | 7.9 | 2.7 |
| 준의 빈티지 | 13 | 4.6 | 2.3 |
| 주말 벼룩시장 | 17 | 8.2 | 4.0 |
| 달빛 가판 | 9 | 4.5 | 2.2 |

**달빛 가판과 초록 온실은 파는 것 자체가 적다.** 아홉 개 · 열한 개뿐이라
진열을 아무리 좁혀도 며칠이면 다 보게 된다. 이건 규칙으로 못 고치고 그림이 더 있어야 한다.

### 처음 만났을 때만

처음 얻으면 `NEW DISCOVERY` 를 띄우고 도감이 한 칸 는다.
**두 번째부터는 안 띄운다.** 같은 연출을 세 번 보면 네 번째부터는 그냥 닫아야 하는 창이 된다.
그때는 `샀어 · 🪙 -120` 한 줄이면 충분하다.

### 도감

가방은 "지금 쓸 수 있는 것", 도감은 "지금까지 만난 것" 이다. 그래서 BAG 안에서 갈라뒀다.
아직 못 만난 칸도 지우지 않는다 — 빈 칸이 있어야 채우고 싶어진다.

한 번에 60칸씩 그린다. 240칸을 한꺼번에 그리면 폰에서 스크롤이 먼저 무거워진다.

### 만들기

퀘스트를 끝내다 보면 재료가 나온다 (나무조각·천·유리·금속·종이·잎·꽃잎·돌).
별 조각·별가루·달가루·꿈 조각처럼 그 자체로 예쁜 것은 따로 만들지 않고 도감 물건을 그대로 쓴다.

`집 → 작은 작업실` 에서 만든다. **모든 레시피를 처음부터 보여주지 않는다.**
아직 모르는 건 몇 개 남았는지만 알려주고, 레벨·도감·세트·사람을 통해 하나씩 알게 된다.

### 트로피

현실에서 쌓은 것을 방에 놓을 수 있는 물건으로 바꾼다.
첫 퀘스트의 작은 나무별부터 천 개의 별이 든 병까지 12개.

**능력치는 하나도 안 붙는다.** 붙이는 순간 "효율 때문에 놓는 것" 이 되고,
그러면 예쁜 걸 놓을 자리가 없어진다.

### 방 꾸미기

HOME 카드의 `꾸미기` 를 누르면 방 편집으로 들어간다.
격자에 맞추지 않고 자유 좌표(방 크기 대비 %)로 둔다 — 조금 삐뚤어도 그게 더 사람 방 같다.

**앞뒤는 저장하지 않고 y 좌표로 정한다.** 아래에 있는 것이 앞에 온다. 실제 방도 그렇게 보인다.

- 아무것도 안 놓은 방은 원래 그림 그대로다. 첫날부터 텅 빈 방을 보여주면 그건 시작이 아니라 숙제다
- 방은 6개. 거실은 Lv.10, 부엌·작업실·취미방은 그 분야 퀘스트 30개, 발코니는 도감 60개
- **방에 점수를 매기지 않는다.** 예쁘게 꾸몄는지 평가하는 숫자는 어디에도 없다

### 그림

물건 하나를 그리는 순서는 셋이다: **그려둔 그림 → 이모지 → 분류별 실루엣.**

- 도감 **240개 전부**에 진짜 그림이 있다 (트로피 12개 · 재료 8개 포함해 파일 259장)
- **이모지로 때우는 자리는 없다.** 이모지는 폰마다 모양이 달라서, 한 칸만 결이 다르게 보인다
- 전부 시트에서 뽑은 그림이다. 코드로 그려 넣은 것은 하나도 없다

빈 네모나 깨진 글자가 나오는 자리는 없다.

이모지 자리는 코드에 남겨뒀다. 앞으로 물건을 먼저 넣고 그림을 나중에 그릴 때
그 사이에 빈칸이 보이면 안 되기 때문이다.

그림 목록은 `lib/collection/assets.ts` 한 곳에 있다. **아이템 표에는 파일 경로를 적지 않는다** —
그림은 나중에 하나씩 채워지는 것이라, 표와 폴더가 어긋나기 십상이다.
목록에 id 한 줄만 더하면 경로는 분류에서 자동으로 만들어지고,
도감·상점·방·가방이 전부 알아서 쓴다.

도감 그림 248장(4.2MB)은 **첫 실행에 한꺼번에 받지 않는다.**
처음 보는 순간 받아서 캐시에 남으니, 두 번째부터는 오프라인에서도 뜬다.

### 그림 파이프라인

원본 시트를 자르는 것부터 카탈로그에 붙기까지 다섯 단계다. 전부 다시 돌릴 수 있다.

```bash
npm run assets:extract    # 원본 시트 → public/assets/collection/<id>.webp
npm run assets:manifest   # 분류 폴더로 옮기고 src/data/asset-manifest.json 갱신
npm run assets:thumbs     # 도감용 작은 그림 128px
npm run assets:audit      # 빠진 것 · 깨진 경로 · 중복 → reports/asset-audit.md
npm run assets:index      # 259장 대조표 → reports/asset-index.html
```

- **원본 시트는 고치지 않는다.** `assets/source-sheets/` 에 투명 PNG 그대로 두고,
  자를 때마다 여기서 다시 뽑는다. 처음 받은 시트 15장은 40MB라 저장소에 넣지 않았고
  (`.gitignore`), 나중에 받은 `extra.png` · `trophy.png` 두 장은 합쳐 4MB 뿐이라 넣어뒀다.
  그 둘은 지금 그 그림들의 유일한 사본이다.
- **다시 뽑으면 갈아끼운다.** `assets:extract` 로 나온 것이 평면 폴더에 있으면
  `assets:manifest` 가 기존 파일 위에 덮는다. 시트가 원본이니 그게 맞는 그림이다.
- 파일 이름은 아이템 id 그대로 `snake_case`. 한글·공백·대문자를 쓰지 않는다.
- 물건마다 흰 테두리(스티커 선)가 둘린 시트는 `PARAMS` 에 `sticker=True` 를 준다.
  그 선을 그대로 두면 방에 놓았을 때 그 물건만 오려붙인 것처럼 보인다.
  **바깥에서 이어져 들어오는 흰 덩어리만** 벗기니까, 크림색 빈백처럼 몸통이 밝은 것은
  파먹지 않는다 — 그것들은 순백이 아니다.
- 파일은 분류별 폴더에 들어간다 — `public/assets/items/furniture/cream_bed.webp`.
  248장이 한 폴더에 있으면 사람이 눈으로 대조할 수가 없다.
- `assets:audit` 는 깨진 경로·중복이 하나라도 있으면 **1로 끝난다.** 조용히 넘어가지 않는다.
- 같은 점검을 `src/lib/__tests__/assets.test.ts` 에서도 한다.
  빌드 전에 잡히라고 두 군데 둔 것이다.
- 어느 물건이 어느 시트 몇 번째에서 나왔는지는 매니페스트의 `source` · `sourceIndex` 에 남는다.
  시트가 저장소에 없어도 출처는 남아 있어야 한다.
- 시트에 있었지만 아직 아무 물건에도 안 붙은 조각은 `assets/alternates/` 에 넣어뒀다.
  **버리지 않는다.** 물건이 늘어나면 거기서 먼저 찾는다.

#### 그림이 없으면 그리지 말고 요청한다

**시트에 없는 물건은 코드로 그려 넣지 않는다.** 색과 선 굵기를 맞춰도
붓질이 달라서 도감에 나란히 놓으면 그 칸만 티가 난다.
없으면 무엇이 없는지 목록으로 정리해서 그림을 받아온다.

`npm run assets:audit` 이 그 목록을 만든다 — "그림이 없는 물건" 칸을 보면 된다.
지금은 비어 있다.

한동안 트로피 다섯 개를 SVG 로 그려서 채워뒀었다. 시트가 와서 전부 바꾸고
그리는 코드도 같이 지웠다. 안 쓸 길은 남겨두지 않는다.

#### 대조표

`npm run assets:index` 로 `reports/asset-index.html` 을 만든다.
259장을 분류별로 늘어놓고 이름·id·놓는 자리·어느 시트에서 나왔는지를 밑에 적는다.

폴더에서 파일을 하나씩 열어보면 **잘못 붙은 그림은 절대 안 보인다.**
한 화면에 늘어놓으면 그때 보인다. 앱에는 들어가지 않는다.

#### 큰 그림 · 작은 그림

같은 그림을 두 벌 둔다.

| | 크기 | 쓰는 곳 |
| --- | --- | --- |
| `public/assets/items/` | 긴 쪽 320px | 방 · 도감 상세 |
| `public/assets/thumbs/` | 긴 쪽 128px | 도감 격자 · 상점 · 가방 |

도감 한 칸은 폰에서 32~56px 다. 240칸을 훑는데 320px 짜리를 다 받으면
필요 없는 데이터를 몇 배로 받는다. 한 바퀴에 **2.7MB** 덜 받는다.

### 어디에 놓는 물건인가

물건마다 `placementType` 이 있다 — 바닥 · 벽 · 위에 올리기 · 매달기 · 깔개 · 창가 · 선반 · 장식.
`lib/collection/placement.ts` 한 곳에서 **분류 기본값 → 하위분류 → 아이템** 순으로 겹쳐 정한다.
240줄을 하나하나 적으면 대부분이 같은 값인 표가 두 배로 길어진다.

여기서 나오는 것:

| | 쓰는 곳 |
| --- | --- |
| `layer` | 앞뒤 순서. **러그는 늘 가구 밑에 깔린다** |
| `defaultScale` | 방 너비의 몇 %를 차지하는지 (침대 32%, 머그컵 10%) |
| `anchor` | 벽에 거는 것은 가운데, 바닥에 서는 것은 밑변 |
| `placement` | 방에 놓을 수 있는지(`PLACEABLE`) · 도감에만(`DISPLAY_ONLY`) · 재료(`MATERIAL_ONLY`) |

같은 층 안에서는 아래(y)에 있는 것이 앞에 온다. 층이 다르면 층이 이긴다.
그래서 러그를 나중에 놓아도 침대를 덮지 않는다.

재료는 방에 못 놓는다. 먹을 것도 대부분 도감에만 두고, 접시·바구니처럼
놓아두면 그림이 되는 것 여덟 개만 열어뒀다.

### 그림이 없을 때

- 아직 못 본 물건은 **가지고 있는 그림을 어둡게 깔아 실루엣으로** 보여준다.
  모양이 보이면 "저건 뭐지" 가 되고, 네모만 보이면 그냥 빈칸이다.
- 히든은 실루엣도 안 보여준다. 그건 일부러 감춘 것이다.
- 그림 파일 자체가 없으면 이모지, 그것도 없으면 분류별 기본 실루엣.
  지금은 240개 전부 그림이 있어서 이 길로 내려갈 일이 없지만, 코드는 남겨뒀다.
- 그림은 `loading="lazy"`. 화면에 안 들어온 것은 받지 않는다.
- 로딩에 실패하면(`onError`) 조용히 이모지로 내려간다. 깨진 이미지 아이콘은 안 뜬다.

### 되돌리기

퀘스트 완료를 되돌리면 이때 나온 재료·수집품도 정확히 돌아간다.
**그때 처음 본 것이었으면 도감에서도 지운다** — 안 그러면 완료·되돌리기를 반복해서 도감만 채울 수 있다.
재료로 써서 없어진 것은 도감에 남는다. 썼다고 만난 적이 없어지는 건 아니다.

| 무엇을 발견했는지 | 열린 방 |
| 몇 개 가졌는지 | 완성한 세트 |
| 어디에 놓았는지 | 걸 수 있는 방 공기 |
| 찾는 물건 (♥) | 아는 레시피 |
| 받은 보상 (한 번만 받으려고) | 오늘 가게 진열 · 남은 재고 · 오늘의 발견 |
| 무엇을 이미 봤는지 (발견 층) | 자동 컬렉션 진행도 · 비밀 장소 진행도 · 힌트 단계 |

계산할 수 있는 걸 저장해두면 나중에 세트 내용이나 조건을 바꿨을 때 저장된 값과 어긋난다.

### 기존 데이터

`STATE_VERSION = 6`. `collection` · `categoryCompleted` · `bossClears` 만 새로 채운다.

분야별 완료 수는 예전 저장본에 없어서 **남아 있는 퀘스트에서 센다.**
지운 퀘스트는 셀 방법이 없고, 그건 그대로 인정한다 — 0 에서 시작하는 것보다는 훨씬 실제에 가깝다.

없어진 물건이 저장돼 있으면 조용히 버리고, 방에 놓여 있던 것도 같이 거둔다.
가진 개수보다 많이 놓여 있으면 뒤에서부터 정리한다.

**앱을 열 때 한 번, 그동안 조건을 이미 넘긴 것들이 도착한다** —
평판으로 받는 물건, 완성해둔 세트, 트로피. 다음에 뭘 하기 전까지 기다리게 두지 않는다.

## 캐릭터 모습

캐릭터 외형은 **완성된 그림 한 장**으로 정해진다. 머리부터 신발, 들고 있는 것까지
한 장에 다 들어 있다. 모습을 바꾸는 건 `user.selectedSkinId` 한 줄을 바꾸는 일이다.

옷 · 헤어 · 표정을 레이어로 겹치는 쪽을 먼저 만들어봤다가 접었다.
조합 가짓수가 늘수록 "어떤 조합이든 어색하지 않게" 그리는 일이 감당이 안 됐고,
완성된 한 장이 훨씬 예뻤다. 새 모습을 더하는 것도 이제 그림 한 장이면 끝난다
(`SKINS` 에 한 줄 + `public/assets/characters/<id>.webp`).

### 능력치가 없다

EXP 도 코인도 스탯도 붙이지 않는다. 붙이는 순간 "예쁜 것" 과 "효율적인 것" 이 갈라지고,
사람들은 안 예쁜 걸 입게 된다. 그건 이 기능의 목적이 아니다.
(테스트가 이걸 붙잡는다 — 모습을 얻어도 코인 · EXP · 스탯이 그대로인지 확인한다)

### 조건 얼개

조건은 **여럿을 한꺼번에** 걸 수 있고, 진행률은 평균이 아니라 **제일 덜 온 것**으로 본다.
넷 중 셋을 채워도 하나가 0 이면 아직 못 얻는 게 맞고, 평균으로 75% 라고 해놓고
안 열리면 더 답답하다.

셀 수 있는 것 — 분야별 퀘스트 · 시간대 · 동네 평판 · 사람별 친밀도 · 친밀도 합 ·
계절 · 비밀 장소(하나 / 개수) · 이야기(한 장 / 장수) · 도감(전체 / 갈래 / 묶음) ·
세트 완성 수 · 보스 클리어 · 다른 모습 보유 · 특별 이상 모습 개수.

**묶음**(달콤한 것 · 말랑한 것 · 꽃 · 별 · 음악 · 보물)은 도감 분류를 가로지른다.
물건 id 를 손으로 적어두지 않고 이름과 분류를 보고 그때그때 고른다
(`lib/character/groups.ts`) — 딸기 케이크를 도감에 새로 넣으면 여기 손대지 않아도
달콤한 것에 들어온다. 테스트가 묶음이 비지 않았는지 확인한다.

조건은 **전부 이미 쌓여 있는 기록에서 센다** — 발견 층과 같은 방식이다.
따로 적립하지 않으니 나중에 조건을 바꿔도 저장된 값과 어긋나지 않고,
이 업데이트를 켜는 순간 그동안의 기록이 그대로 반영된다.

화면에는 조건 숫자를 적지 않는다. 힌트는 분위기만 말한다 —
"몸 퀘스트 30개" 를 적어두면 그건 발견이 아니라 과제 목록이다.
(테스트가 힌트에 숫자가 없는지 확인한다)

### 얻어도 저절로 갈아입히지 않는다

새 모습이 생기면 한 번 보여주고(`NewSkinOverlay`), 입는 건 사람이 고른다.
그 카드에는 모습마다 다른 두 줄이 같이 나온다 — "June이 작은 상자를 내밀었다." 같은.
얻자마자 바꿔버리면 아침에 열었더니 고른 적 없는 모습이 서 있게 된다.

반대로 **고른 것은 즉시 바뀐다.** 고르기 → 적용 → 저장 같은 단계를 두지 않았다.
"적용" 버튼을 만들면 사람들은 그걸 안 누르고 나가서 왜 안 바뀌냐고 한다.

### 빈 자리를 만들지 않는다

그림을 못 받으면 기본 모습으로, 그것도 못 받으면 처음부터 있던 캐릭터 그림으로 내려간다.
깨진 그림 아이콘은 어떤 경우에도 안 보인다. 시트를 아직 안 넣었거나
배포가 반쯤 갈렸을 때 실제로 생기는 일이다.

저장된 값이 이상해도 마찬가지다. 모르는 id 는 버리고, 안 가진 걸 입고 있다고
적혀 있으면 기본으로 돌린다 — 입을 게 하나도 없는 상태가 되면 안 된다.

### 그림 자르기

시트마다 배경이 다르다 — 1차 세 장은 흰 배경, 2차 세 장은 투명이다.
어느 쪽인지는 파일 테두리를 보고 알아서 정한다. 흰 배경일 때는
**가장자리와 이어진 흰색만** 지운다. 전체를 밝기로 자르면 크림색 후드와
흰 양말까지 사라지는데, 옷 안쪽의 흰색은 윤곽선에 둘러싸여 있어서 살아남는다.

시트마다 그림 크기도 다르다 (1차 1122x1402, 2차 1254x1254). 그대로 자르면 크기가 어긋난다.
그래서 시트마다 **네 명의 키 중앙값**을 재서 같은 키가 되게 맞춘다 —
중앙값이라 우산 하나가 솟아 있어도 흔들리지 않는다.

그 다음 스물넷을 같은 크기 캔버스에 올리고 발끝을 같은 줄에 맞춘다.
가운데는 상자가 아니라 **발** 기준으로 잡는다 (우산이나 등불 쪽으로 밀리지 않게).

결과는 스물넷의 몸 높이가 중앙값 대비 0.95~1.02 안에 든다 (우산과 등불을 뺀 몸통 기준).
그래서 `scale` · `offsetX` · `offsetY` 는 스물넷 다 비어 있다 — 손볼 게 없었다.
쓸 일이 생기면 정의에 적으면 렌더러가 그대로 적용한다 (화면마다 margin 을 주지 않으려고 둔 자리다).
테스트가 "보정값이 비어 있는지" 와 "스물네 장이 실제로 있는지" 를 붙잡는다.

### 자세

지금 화면에서 쓰는 건 서 있는 한 장(`idle`)이다.
기본 모습만 처음부터 있던 네 자세(기뻐하기 · 레벨업 · 쉬기)를 그대로 쓴다.
나머지 열한 벌은 그 순간에도 같은 그림으로 폴짝 뛴다 — 움직임은 그대로 살아 있다.
자세 그림이 생기면 `poses` 에 더하면 되고, 없는 자세는 알아서 idle 로 돌아간다.

### 알아두면 걸리는 자리

투명 배경인지 흰 배경인지를 **테두리에서 제일 밝은 한 점**으로 판단하면 안 된다.
투명 시트에도 테두리에 반쯤 살아 있는 점 하나쯤은 남아 있고 (실제로 `skins-3.png` 가
그랬다), 그것 때문에 흰 배경으로 오해하면 전체가 불투명해진다.
테두리가 거의 다 비어 있는지(1% 미만)로 본다.

### 개발용 갤러리

주소에 `?dev=skins` 를 붙이면 스물넷을 한 줄에 세워놓고 크기와 정렬을 볼 수 있다.
바닥에 그은 선에 발끝이 닿아 있어야 한다. 화면 어디에도 들어가는 길은 없다.

**전부 지급** 버튼으로 조건을 채우지 않고도 전부 볼 수 있고, 그림을 누르면
그 자리에서 입어본다. 각 줄에 파일 크기 · 획득 경로 · 진행률 · 값 · 해금 대사가 나온다.

## 처음 안내

앱을 처음 열면 여덟 장짜리 안내가 한 번 뜬다. 나중에는 **나 › 앱 사용법**에서 언제든 다시 연다.

### 왜 필요했나

동료도 비밀 장소도 "조건을 채우면 알아서 나타나는" 구조로 만들었다.
발견하는 재미를 위한 선택이었는데, 그런 게 있다는 것 자체를 아무도 말해주지 않으면
발견이 아니라 그냥 없는 것이 된다. 실제로 "내 펫은 어디 있어?" 라는 질문을 받고 만들었다.

### 여덟 장

| | 무엇을 |
| --- | --- |
| 환영 | 여기서 하는 건 하나 — 적고, 끝내면 표시 |
| 퀘스트 | ＋ · 동그라미 · 추천 · 반복, 그리고 여섯 갈래 |
| 도시와 사람들 | 동네 고르기 · 평판 · NPC · 의뢰 |
| 도감 | 물건이 생기는 길 세 가지, 매일 바뀌는 진열, ♡ |
| 내 방 꾸미기 | 놓기 · 옮기기 · 세트로 열리는 공기 |
| **같이 다니는 아이들** | **넷과 만나는 조건** |
| 발견함 | 자동 컬렉션 · 비밀 장소 |
| 마무리 | 천천히 해도 된다 · 다시 보는 곳 |

### 조건은 손으로 적지 않는다

동료 장에 나오는 "초록 공원에서 평판 12" 는 안내 파일에 적혀 있지 않다.
`COMPANIONS` 정의에서 `meetingLabel()` 이 만들어낸다. 조건을 바꾸면 안내도 같이 바뀐다 —
손으로 적어두면 언젠가 안내만 옛말이 되는데, 그건 안내가 없는 것보다 나쁘다.
(테스트가 이걸 붙잡고 있다: 숫자를 바꾸면 문장도 바뀌는지 확인한다)

이미 만난 아이는 "만났어" 로 바뀌고, 가는 중이면 얼마나 왔는지 가는 줄로 보여준다.
몇 번 남았는지는 세지 않는다.

### 지키는 것

- **끝까지 봐야 닫히지 않는다.** 아무 장에서나 닫을 수 있고, 닫으면 본 것으로 친다.
- **다시 조르지 않는다.** `guideSeenAt` 이 한 번 적히면 그걸로 끝이다.
- **설정에서 다시 열어도 그 날짜는 안 바뀐다.** "본 적 있는지" 를 적는 것이지
  "마지막으로 본 때" 가 아니다.
- **높이를 붙잡아 둔다.** 장마다 글 길이가 다른데 높이를 내용에 맡기면 넘길 때마다
  시트 윗변이 손가락 밑에서 오르내린다. `BottomSheet` 의 `fill` 이 이 자리를 위해 있다.
- **다그치는 말을 쓰지 않는다.** 여기 있는 것 중에 안 하면 손해인 건 없다.
- **새 그림을 만들지 않았다.** 이미 있는 캐릭터 · 배지 · 방 · 동료 그림과 이모지만 쓴다.

```
src/lib/guide/pages.ts              여덟 장의 내용
src/components/guide/GuideSheet.tsx 넘기기 · 동료 조건 표
src/lib/discovery/companions.ts     meetingLabel() — 조건을 사람 말로
```


## 파일로 옮기기

계정도 서버도 없이 폰을 바꿀 수 있는 길. 설정 › 백업 › **파일로 옮기기** 에 있다.
클라우드를 안 켰어도 늘 나온다.

예전 폰에서 "파일로 내보내기" → 새 폰에서 "파일에서 가져오기" 로 파일을 고르면
그대로 이어진다. 클라우드를 같이 쓰더라도 이건 그대로 쓸모가 있다 —
큰일 하기 전에 손으로 남겨두는 사본.

### 폰에서는 내려받기가 잘 안 통한다

홈 화면에 올려둔 PWA 안에서 `<a download>` 를 누르면 기기에 따라
아무 일도 안 일어난 것처럼 보인다. 어디로 갔는지 알 수가 없다.
그래서 손가락으로 쓰는 기기(`pointer: coarse`)에서는 **공유 시트**를 먼저 연다.
"파일에 저장" 도 있고 자기한테 메일로 보내기도 있어서, 어디로 갔는지 눈으로 본다.
마우스 쓰는 데서는 평범하게 내려받는다. (`lib/sync/download.ts`)

가져올 때 `accept` 에 MIME 만 적으면 아이폰 파일 앱에서 json 이 회색으로 죽는다.
확장자(`.json`)를 같이 적어둬야 고를 수 있다.

### 파일 모양

안을 열어봤을 때 이게 뭔지 알 수 있어야 한다. 상태만 덜렁 넣지 않는다.

```json
{
  "app": "little-life",
  "kind": "backup",
  "formatVersion": 1,
  "stateVersion": 9,
  "exportedAt": "2026-08-24T10:00:00.000Z",
  "summary": { "level": 7, "completed": 63, "discovered": 41, "days": 22, ... },
  "state": { ... }
}
```

`summary` 는 사람이 눈으로 보라고 넣는 것뿐이다. 읽을 때는 쓰지 않는다 —
저장된 값을 믿기 시작하면 언젠가 실제와 어긋난다.

### 이상한 파일을 그냥 앉히지 않는다

들어오는 문은 저장된 것을 읽을 때와 같다 (`sanitizeState`). 그래서
예전 판본으로 내보낸 파일도 지금 판본으로 끌어올려 받는다.
남의 앱 파일, 깨진 글자, 빈 껍데기는 이유를 말해주고 거른다 —
조용히 백지로 시작하는 경우가 하나도 없어야 한다.

가져오기 전에 양쪽에 뭐가 들었는지 나란히 보여주고 한 번 물어본다.
누르고 나서도 덮이기 직전 기록은 한 벌 남아서, 설정에서 되돌릴 수 있다.


## 클라우드 백업

폰을 바꾸거나 잃어버려도 기록이 이어지게, Supabase 에 한 벌 올려둔다.
안 켜면 예전과 똑같이 폰 안에만 저장한다 — 환경변수가 없으면
설정 화면에 그 칸 자체가 안 나온다.

### 켜는 순서

1. [supabase.com](https://supabase.com) 에서 프로젝트를 하나 만든다 (무료로 충분하다).
2. SQL Editor 에 `supabase/schema.sql` 을 붙여넣고 실행한다.
   여러 번 실행해도 안전하다.
3. Settings › API 에서 **Project URL** 과 **anon public** 키를 복사한다.
4. Vercel › Settings › Environment Variables 에 넣는다.

   ```
   VITE_SUPABASE_URL       = https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY  = eyJhbGciOi...
   ```

   로컬에서 쓰려면 `.env.example` 을 `.env.local` 로 복사해 같은 값을 넣는다.
5. 다시 배포한다. 설정 화면 맨 아래에 "백업" 칸이 생긴다.

anon 키는 앱 번들에 그대로 들어간다. 공개돼도 되는 키지만,
**2번을 건너뛰면 안 된다** — 남의 줄을 막는 건 RLS 뿐이다.

### 로그인

메일로 먼저 들어오고, 그 다음에 설정에서 비밀번호를 걸면
다음부터는 비밀번호로 바로 들어올 수 있다.

메일 링크에는 폰에서 걸리는 문제가 하나 있다. 메일 앱에서 링크를 누르면
대개 메일 앱 안의 브라우저가 열리는데, 거기서 로그인이 되면 정작
홈 화면에 깔아둔 앱은 그대로 로그아웃 상태다. 그래서 로그인 화면에
**숫자 여섯 자리를 손으로 넣는 길**도 같이 뒀다. 그 쪽이 폰에서는 더 편하다.

숫자를 받으려면 메일 서식에 토큰이 들어 있어야 한다.
Supabase › Authentication › Email Templates › Magic Link 에서 한 줄 넣는다.

```html
<p>이 숫자를 앱에 넣어도 됩니다: <b>{{ .Token }}</b></p>
```

Site URL 과 Redirect URLs 에는 배포 주소(`https://…vercel.app`)를 넣어둔다.

### 어느 쪽을 남길지

이 기능에서 제일 조심한 자리다. **확실하지 않으면 덮어쓰지 않고 물어본다.**

줄마다 판본 번호(`rev`)가 있고, 기기는 "내가 마지막으로 맞춰본 판본"을 들고 있다.
올릴 때 "그 판본이 아직 그대로일 때만" 이라는 조건을 걸기 때문에,
그 사이 다른 기기가 올렸으면 업데이트가 0줄로 끝나고 앱이 그걸 알아챈다.

| 상황 | 하는 일 |
| --- | --- |
| 클라우드가 비어 있다 | 올린다 |
| 판본이 같고 이 기기만 바뀌었다 | 올린다 |
| 판본이 같고 바뀐 것도 없다 | 아무것도 안 한다 |
| 클라우드만 앞섰고 이 기기는 그대로다 | 받아온다 (이 기기 것은 클라우드의 예전 모습이다) |
| 갓 깐 기기에서 처음 연결했다 | 받아온다 (잃을 게 없다) |
| **양쪽에서 각각 바뀌었다** | **물어본다** |
| **처음 연결인데 양쪽 다 기록이 있다** | **물어본다** |

물어볼 때는 양쪽에 뭐가 들었는지 숫자로 보여준다 (레벨 · 끝낸 것 · 도감 · 기록한 날).
"기기 / 클라우드" 라고만 쓰면 아무도 못 고른다.

### 덮어쓰기 전에는 사본을 남긴다

클라우드 것을 받아오기 직전 상태를 `little-life-backup-v1` 에 한 벌 남긴다.
설정 화면에 "되돌리기" 가 같이 뜬다. 잘못 골랐어도 되돌아갈 자리가 있다.

### 게임 상태는 건드리지 않는다

동기화 층은 게임 규칙을 하나도 모른다. 상태 한 덩어리를 올리고 받아올 뿐이다.
퀘스트를 합치거나 코인을 더하지 않는다 — 그런 걸 시작하면 보상 계산이
두 벌이 되고 어느 쪽이 맞는지 아무도 모르게 된다.

받아온 상태에도 보상 계산을 다시 돌리지 않는다 (`replaceState`).
다른 기기가 이미 계산을 마친 결과라서, 여기서 한 번 더 돌리면 두 번 주게 된다.

### 저장 구조는 그대로다

이 기능 때문에 `AppState` 에 늘어난 항목이 하나도 없다. 판올림도 없다 (v9 그대로).
동기화가 기억해야 하는 건 "이 기기가 클라우드와 어디까지 맞춰 놨는지" 인데,
그건 이 기기만 아는 값이라 게임 상태 안에 넣으면 안 된다 —
넣으면 그대로 클라우드에 올라가서, 다른 기기가 남의 기기 기록을 자기 것으로 착각한다.
그래서 저장 열쇠부터 따로 뒀다 (`little-life-sync-v1`).

### 라이브러리는 쓸 때만 받는다

`@supabase/supabase-js` 는 gzip 으로도 58KB 다. 백업을 안 쓰는 사람에게까지
첫 화면에서 받게 할 이유가 없어서 `import()` 로 잘라뒀고,
서비스 워커의 미리받기 목록에서도 뺐다 (`vite.config.ts`).
쓰기 시작하면 그때 받아서 캐시에 남는다.

### 관련 파일

```
supabase/schema.sql          표 · 트리거 · RLS
src/lib/sync/config.ts       환경변수와 켜짐 여부
src/lib/sync/client.ts       지연 로딩 · 오류 문구 한국어로
src/lib/sync/local.ts        이 기기만 아는 기록 (판본 · 지문 · 마지막 이메일)
src/lib/sync/backup.ts       덮어쓰기 전 사본
src/lib/sync/merge.ts        어느 쪽으로 갈지 판단 · 요약
src/lib/sync/remote.ts       표 읽기 · 낙관적 잠금 올리기
src/hooks/useSync.ts         전체 흐름
src/lib/sync/file.ts         내보낼 파일 만들기 · 가져온 파일 읽기
src/lib/sync/download.ts     공유 시트 / 내려받기
src/components/sync/         로그인 · 비밀번호 · 충돌 · 가져오기 · 설정 칸
```

## 작은 정원

초록 공원 너머에 정원 하나. `?dev=garden` 으로 검수판이 열린다.

### 이건 농사 게임이 아니다

넣지 않은 것, 그리고 앞으로도 넣지 않을 것:

- 매일 물 주기
- 물을 안 주면 죽는 작물 · 시듦 · 썩음
- 연속 출석 조건
- 안 들어오면 손해 보는 구조
- 정원을 해야 퀘스트를 할 수 있는 구조

며칠을 안 봐도 심어둔 것은 다 자란 채로 서서 기다린다.
정원이 현실의 숙제를 늘리는 순간 이 기능은 실패한 것이다.

### 저장하는 건 두 가지뿐

```
garden.plots                 지금 무엇이 심겨 있는지
garden.harvestedCropCounts   무엇을 몇 번 거뒀는지
```

레벨 · 경험치 · 밭 개수 · 발견한 작물은 저장하지 않는다. 전부 위 두 값에서 센다
(`lib/garden/derive.ts`). 그래서 나중에 필요 경험치를 손봐도 저장된 값과 어긋나지 않고,
이 업데이트를 처음 켜는 사람에게 따로 채워 넣는 코드가 필요 없다.

밭이 지금 비었는지 자라는 중인지 다 자랐는지도 저장하지 않는다.
`plantedAt` 과 `readyAt` 을 지금 시각과 견줘서 그때그때 정한다 —
저장해두면 앱을 열어보기 전까지 계속 "자라는 중" 인 채로 멈춰 있게 된다.

### 다 자랄 시각은 심을 때 굳힌다

`readyAt` 을 심는 순간 계산해서 박아둔다. 퀘스트의 `exp` 를 굳혀두는 것과 같은 이유로,
나중에 자라는 시간을 바꿔도 이미 심어둔 것의 약속은 흔들리지 않는다.
퀘스트로 받는 성장 단축도 여기서 `readyAt` 을 앞당기는 것으로 끝난다.

### 작물 12종

씨앗이 도는 여덟 가지 (딸기 · 토마토 · 감자 · 바질 · 라벤더 · 당근 · 호박 · 작은 버섯)와
아직 안 도는 네 가지 (별빛꽃 · 달빛허브 · 꿈딸기 · 황금 딸기).
뒤의 넷은 도감에 ??? 로 자리만 있다 — 만날 방법을 급하게 지어내지 않았다.

자라는 시간은 3~10시간. "아침에 심으면 저녁에 거둔다" 를 기준으로 잡았다.
이보다 짧으면 앱을 붙들고 있게 되고, 이보다 길면 심어둔 걸 잊는다.

### 도감 240칸은 그대로다

작물은 도감의 240칸에 들어가지 않는다. 도감을 이미 채워둔 사람의 `184 / 240` 이
어느 날 `184 / 264` 가 되면 그건 새 콘텐츠가 아니라 뒷걸음질처럼 보인다.
작물은 도감 안에 자기 칸(작물 n/12)을 따로 가진다.

씨앗도 재료 목록(`MATERIAL_CATALOG`)에 섞지 않았다. 그 목록은 퀘스트 드롭 풀이기도 해서,
섞으면 기존 재료가 나올 확률이 조용히 낮아진다. 씨앗은 자기 굴림을 따로 가진다.

### 퀘스트에서 오는 것

기존 보상 계산은 한 줄도 손대지 않았다. EXP · 코인 · 장비 드롭 · 재료 드롭은 그대로 돌고,
그 위에 따로 얹히는 굴림이 셋 있다:

| | 일반 | Hard | 보스 |
|---|---|---|---|
| 씨앗 | 20% | 30% | 50% |
| 성장 단축 | 10분 | 15분 | 30분 |
| 모험 에너지 | +1 | +2 | +3 |

아침 이슬은 4%. 정원을 아직 못 찾았으면 셋 다 아무것도 안 나온다 —
쓸 데 없는 씨앗이 가방에 먼저 쌓여 있으면 그건 힌트가 아니라 잡동사니다.

분야별 기울기는 아주 약하다 (맞는 씨앗의 무게가 두 배). 어떤 씨앗도 특정 분야에서만
나오지 않는다. "라벤더를 얻으려면 마음 퀘스트를 해야 한다" 가 되는 순간
정원이 오늘 뭘 할지를 고르기 시작한다.

받은 것은 전부 `quest.reward` 에 적어둔다. 되돌리기가 정확히 반대로 돌아야 하기 때문이다 —
씨앗도 이슬도 에너지도, 앞당겨준 밭까지. 그 사이 거두고 다시 심은 칸은 건너뛴다.

### 모험 에너지

퀘스트를 끝내면 조금씩 쌓이고 10에서 멈춘다. **지금은 쓰는 곳이 없다.**
앞으로 들어올 광산·던전 같은 곁가지를 위한 자리다.
퀘스트에도, 캐릭터 성장에도, 정원이 자라는 데도 필요하지 않다 —
0이어도 오늘 할 수 있는 일은 하나도 줄지 않는다.
쓰는 곳이 없는 동안에는 화면에 띄우지 않는다 (검수판에서만 보인다).

### 정원을 찾는 조건

초록 공원 평판 6 **그리고** 생활·몸·마음 퀘스트 합계 10개.
둘 다 "지금까지 몇 번" 이라 되돌아갈 수가 없다 — 며칠 쉬었다고 조건이 멀어지지 않는다.
평균이 아니라 제일 덜 온 쪽을 본다.

### 관련 파일

```
src/types/garden.ts              작물 · 밭 · 저장 모양
src/lib/garden/crops.ts          작물 12종 (이 표가 정원의 전부)
src/lib/garden/items.ts          씨앗 · 거둔 것 · 이슬 (작물 표에서 만들어낸다)
src/lib/garden/derive.ts         해금 · 레벨 · 성장 단계 · 심기 · 거두기 · 이슬
src/lib/garden/quest.ts          퀘스트에서 오는 것 (기존 보상과 따로)
src/lib/garden/labels.ts         남은 시간 · 자라는 모습
src/lib/garden/dev.ts            검수용 도구
src/components/garden/           정원 화면 · 씨앗 시트 · 첫 안내 · 수확 카드 · 검수판
```

### 그림이 아직 없다

작물 열두 가지는 지금 이모지 한 글자로 서 있고, 자라는 모습은 작물마다 따로 없이
공용 표시(· → 🌱 → 🌿 → 🌾 → 작물)를 같이 쓴다.
그림이 들어오면 `crops.ts` 의 `icon` 자리와 렌더러만 바꾸면 된다.
