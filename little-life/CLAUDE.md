# LITTLE LIFE

현실의 작은 행동을 퀘스트·탐험·수집·성장으로 바꾸는 현대 생활 판타지 RPG.
Vite + React + TypeScript + Tailwind. 폰에서 쓰는 PWA.

> 재미있는 세계가 궁금해서 현실에서 움직인다.
> 현실에서 움직였기 때문에 세계가 조금 더 열린다.

생산성을 강요하는 앱이 아니다. **현실 행동은 이야기의 입장권이 아니라,
이 세계와 함께 살아온 기록이다.**

자세한 방향은 `docs/direction/` 여덟 장에 있다. 새 기능을 설계하기 전에 읽는다.

---

## 절대 규칙

사용자가 직접 말하지 않는 한 이 선을 넘지 않는다.

### 사람을 대하는 방식

- **꾸중하지 않는다.** 연속 출석, 놓친 날 경고, 시무룩한 캐릭터를 만들지 않는다.
- **미접속을 벌주지 않는다.** 하루 안 왔다고 친밀도가 줄거나 관계가 끝나지 않는다.
- **오늘 안 하면 손해인 구조를 만들지 않는다.** 매일 해야 하는 일과 하루 제한은
  그 자체로 숙제다. 실패·패배·랜덤 실패도 만들지 않는다.
- 중요한 장면은 시간을 놓쳤다고 영영 사라지지 않는다.

### 구조

- **파생 가능한 상태를 저장하지 않는다.** 셀 수 있으면 세고, boolean 을 굳히지 않는다.
  (예: 문이 열렸는지는 `doorOpen` 이 아니라 밟은 걸음 목록에서 계산한다.)
- **새 시스템 전에 기존 코드를 먼저 조사한다.** 조사 결과를
  ① 그대로 재사용 ② 작은 확장 ③ 정말 신규 로 나눠 보고한 뒤 구현한다. ③ 은 되도록 없어야 한다.
- **새 화폐 · 새 에너지를 만들지 않는다.** 있는 코인과 `adventureEnergy` 를 쓴다.
  에너지가 0이어도 화면 열람 · 기록 확인 · 이미 연 곳 이동은 된다.
- **보상 계산을 복제하지 않는다.** 한 군데서만 한다.
- 한 업데이트의 범위를 넘지 않는다. 다음 것은 Hook 만 남긴다 —
  **Hook 은 떡밥이지 구현이 아니다.**
- 기존 저장을 깨지 않는다. 신규 필드는 기본값, 모르는 id 는 sanitize 로 걸러낸다.
  중복 지급이 안 생기게 flag 를 챙긴다.

### 그림

- **없는 에셋을 지어내지 않는다.** 코드로 그리지 말고 무엇이 없는지 적어서 요청한다.
  이모지 한 글자가 이 프로젝트의 placeholder 다 (`npm run assets:audit` 이 센다).
- **색 필터로 기존 그림을 다른 물건처럼 쓰지 않는다.** hue-rotate 금지.
- 캐릭터 옷은 **완성된 한 장 = 한 벌**. 상의/하의/머리로 나누는 레이어 방식은
  한 번 만들어봤다가 접었다. 되살리지 않는다.
- 금지: 네온 · 다크판타지 RPG UI · 두꺼운 금테 · 진한 그림자 · 과한 입자.
  파스텔, 낮은 대비, 둥근 실루엣, 은은한 수채 질감.
- 희귀함은 반짝이 입자가 아니라 색조와 재질로 말한다.

### 이름

- **확정명이 없으면 짓지 않는다.** 리포 · 시트 파일명 · 문서 · git 기록을 끝까지 찾고,
  그래도 없으면 자리표(`PACK7_SKIN_73`)로 두고 `nameMissing` 을 켠다.
  id 에도 뜻을 담지 않는다 — 나중에 진짜 이름이 오면 파일명만 딴소리를 하게 된다.
  (실제로 두 번 그랬다.)
- 이름이 오면 **id · 이름 · 그림 파일을 한 번에 같이** 정한다.
- **사람 이름이 바뀌어도 npc id 는 안 바꾼다.** 저장이 친밀도 · 읽은 이야기 ·
  비밀 장소 · 던전 입구를 전부 id 로 붙잡고 있다. 도시 여섯은 이렇게 붙어 있다 —
  `MINA`=윤하루(카페) · `HARU`=윤태오(공원·러닝) · `LULU`=오미래(공방) ·
  `JUNE`=서이안(빈티지숍) · `RIO`=한도윤(클라이밍장) · `NOA`=차세라(밤거리·BAR).
  이야기 장 id(`HARU_5` = 오래된 열쇠)와 가게 id(`MINA_CAFE`, `JUNE_CLOSET`,
  `JUNE_VINTAGE`)도 같은 이유로 옛 이름을 그대로 쓴다. 성격과 관계는
  `docs/direction/06_NPC_CHARACTER_BIBLE.md` 가 기준이다.

## 이 리포에서 일하는 법

작업 디렉터리는 `little-life/` 다. 리포 루트에서 `npm` 을 돌리면 안 된다.

```bash
npm run typecheck     # tsc -b --force  ← 진짜 타입 검사
npx vitest run        # 단위 테스트 (little-life/ 안에서)
npm run assets:audit  # 빠진 그림 · 이름 · 캔버스 점검
npm run assets:skins  # 시트에서 캐릭터 옷 잘라내기
npm run assets:thumbs # 목록용 작은 그림
npm run build
```

**`npx tsc --noEmit` 은 조용히 통과한다. 믿지 마라.** `npm run typecheck` 만 진짜다.

### 브라우저 검수

바뀐 화면은 실제로 열어본다. 미리보기는 이 순서로 띄운다 —
번들 해시를 확인하지 않으면 예전 걸 보고 통과시킨다.

```bash
npm run build && rm -rf /tmp/dist-noenv && cp -r dist /tmp/dist-noenv
pkill -f "[b]in/serve"; (cd /tmp/dist-noenv && npx serve -s -l 4321 &)
curl -s localhost:4321 | grep -o 'index-[A-Za-z0-9_-]*\.js'   # dist/index.html 과 같은지
```

Chromium 은 `/opt/pw-browsers/chromium`, `serviceWorkers: 'block'`, 390×844.

### 캐릭터 그림

`/assets/characters/<skinId>.webp` — 경로를 아는 곳은 `skinArt()` 하나뿐이다.
120장이 전부 **같은 캔버스(433 × 508) · 같은 발 기준선**에 서 있다.
`extract-skins.py` 가 판에 들어온 조각 전부에서 캔버스를 계산하므로
**새 시트만 따로 돌리면 안 된다. 늘 전체를 한 번에 돌린다.**

크기는 감싸는 상자가 정한다. `CharacterSkinRenderer` 에 `className` 으로
`h-[..]` 를 또 주면 안의 `h-full` 과 싸워서 어느 쪽이 이길지 모른다.

## 지금까지 온 길

UPDATE A 정원 → B 부엌 → C 작업실 → D 채석장 → E 오래된 열쇠와 첫 던전
→ F 생명체 넷과 안쪽의 큰 방 → F.5 의상실과 옷 120벌
→ **G 리빙시티 1 — 여섯 사람의 하루 동선과 영업시간** (여기까지 완료)

다음은 **H 맥락 대사** (어디서 언제 만났느냐에 따라 조금 다르게 말한다).
그 뒤 I 선물과 취향 → J 리빙신 → K 개인 이야기 시범 → 코어 1.0 점검.

**F.6 작은 옷장(가챠) 은 로드맵 밖에 있다.** F.5 때 자리는 다 만들어뒀지만
(GACHA 48벌 · pool 넷 · 650 코인), 방향 문서에는 없고 `02` 의 F 절은
가챠를 "만들지 않을 것" 에 적어뒀다. 할지 말지는 사용자가 정한다.

저장 판올림은 **v17**. G 는 저장을 하나도 안 늘렸다 —
누가 어디 있는지도 가게가 열렸는지도 전부 날짜·시각에서 계산한다.

여섯 사람은 G 뒤에 **캐릭터 바이블의 사람으로 갈아끼웠다.** id · 이야기 · 비밀 ·
레시피 · 던전 입구는 그대로 두고 이름 · 성격 · 대사만 바꿨다 (저장 판올림 없음).
도윤(`RIO`)만 혼자 존댓말을 쓴다 — 바이블의 말투 예시가 그렇다. 실수가 아니다.

## 코드를 쓸 때

- 주석은 **왜 그렇게 했는지**를 적는다. 무엇을 하는지는 코드가 말한다.
  특히 한 번 밟은 지뢰는 반드시 적어둔다 — 다음 사람이 같은 걸 밟는다.
- 레시피·데이터를 UI 컴포넌트 안에 하드코딩하지 않는다.
- 말투는 짧고 생활적으로. 게임 문구(`SSR 획득!`, `전설 스킨 해금!`)를 쓰지 않는다.
